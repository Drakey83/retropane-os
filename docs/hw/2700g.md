# Intel 2700G ("Marathon") on the Dell Axim X51v

> Spec v0.2, 2026-10-10. Facts only, per [`../CLEANROOM.md`](../CLEANROOM.md).
> **Sources:** (A) static analysis of Dell's `ddi_2700g.dll` from the user's
> own ROM (WM6.1 A08; identical code in L11 and WM6.5.5 L16), (B) the old Linux
> `mbxfb` register header (register names), (C) AxDroid board code.
> Spec and analysis were done by the same AI session, so this spec should be
> reviewed on its own before drivers rely on it.

## LCD panel timing (3.7" VGA, 480 × 640)

The driver carries a 32-entry panel table (80-byte records: resolution, refresh,
pixel clock, line rate, horizontal/vertical front porch, sync, back porch,
borders, panel size). Decoding was checked against entry 5, which is standard
VESA 640 × 480 @ 60 exactly (16/96/48, 10/2/33, 25.175 MHz).

The X51v panel's working timings, consistent between Dell's table (entry 3) and
AxDroid's independently tested values to within 1 pixel:

| Parameter | Dell entry 3 | AxDroid |
|---|---|---|
| Active | 480 × 640 | 480 × 640 |
| Horizontal front porch / sync / back porch | 88 / 64 / 16 | 87 / 64 / 17 |
| Vertical front porch / sync / back porch | 1 / 2 / 1 | 4 / 2 / 1 |
| Total | 648 × 644 | 648 × 647 |
| Pixel clock | 23.5625 MHz | (PXA divider value) |
| Refresh | 55 Hz (line rate 35.648 kHz) | — |

Confidence: **likely**. The mapping from `Panel = 10` to table entry 3 hasn't
been traced in code yet. The CPLD reports the panel maker in register `0x1E`
(Sharp or Samsung, per AxDroid).

## Display programming model

Field layouts from the public Linux `mbxfb` definitions (B), the encoding as
used by that driver. All timing fields are 12 bits wide, at `[27:16]` and `[11:0]`.

| Register | Offset | Fields |
|---|---|---|
| `GSCTRL` | 0x2000 | `[30:27]` pixel format (0 indexed, 4 ARGB4444, 5 ARGB1555, 6 RGB888, **7 RGB565**, 8 ARGB8888), `[26]` gamma enable, `[21:11]` width − 1, `[10:0]` height − 1 |
| `GBBASE` | 0x2020 | graphics base (0 in mbxfb) |
| `GDRCTRL` | 0x2040 | `0x00FFFFFF` in mbxfb |
| `GSCADR` | 0x2060 | `[31]` stream enable, `[22:0]` plane start address in local memory **/ 16** |
| `GSADR` | 0x20C0 | `[31:22]` stride: bytes per line / 16 − 1; `[21:11]` X start; `[10:0]` Y start |
| `DSCTRL` | 0x2154 | `[31]` sync generator enable, `[5]` blank polarity, `[3]` VS polarity, `[1]` HS polarity |
| `DHT01` | 0x2158 | `HBPS` = hsync; `HT` = total |
| `DHT02` | 0x215C | `HAS` = hsync + back porch; `HLBS` = same |
| `DHT03` | 0x2160 | `HFPS` = HAS + active; `HRBS` = same |
| `DVT01..03` | 0x2164–0x216C | same scheme vertically (`VBPS`/`VT`, `VAS`/`VTBS`, `VFPS`/`VBBS`) |
| `DHDET` / `DVDET` | 0x2314 / 0x2318 | display enable start/end: `HAS`/`HFPS`, `VAS`/`VFPS` |
| `DVECTRL` | 0x2310 | `VEVENT` = VFPS, `VFETCH` = VBPS |

The conventional framebuffer location is local-memory offset `0x60000`.

**X51v panel encoded:** `HBPS` 64, `HAS` 80, `HFPS` 560, `HT` 648; `VBPS` 2, `VAS` 3,
`VFPS` 643, `VT` 644. A 480 × 640 RGB565 plane has stride field 59 (960 bytes / 16 − 1).

Not yet specified: PLL/pixel-clock programming (`DISPPLL`, `PIXCLK*`), local
memory power-up (`LMPWR`) and `SYSCFG`. Under Windows Mobile these are already
configured when RetroPane is launched from SD.

## Physical mappings made by the WM driver

The driver maps hardware through a helper that calls `VirtualAlloc` +
`VirtualCopy` with `PAGE_PHYSICAL` (address >> 8), optionally `PAGE_NOCACHE`:

| Physical | Size | What |
|---|---|---|
| `0x48000000` | 4 KB | PXA27x memory controller (static memory timing for the 2700G's chip select) |
| `0x41300000` | 4 KB | PXA27x clock manager |
| 2700G windows | computed | from a config structure built from `VLIOChipSelect`/`SRAMChipSelect`; five mappings (to be traced) |

It also uses `InterruptInitialize`/`InterruptDone` (the "MarathonISR" interrupt
thread), `KernelIoControl` (OAL queries), `SetKMode`, `VirtualSetAttributes` and
`CacheRangeFlush`.

## Registers the WM driver saves and restores (suspend/resume)

Dell's driver keeps a `{register, saved value}` table. Its order is the
driver's restore order, and the list is the set of registers it considers
essential state. Names are from (B).

1. **System/clocks:** `SYSCFG 0x000`, `PIXCLK 0x048`, `MEMCLK 0x04C`, `M24CLK 0x050`,
   `MBXCLK 0x054`, `SDCLK 0x058`, `PIXCLKDIV 0x05C`, `LCD_CONFIG 0x060`
2. **Local memory controller:** `LMCFG 0x1004`, `LMPWR 0x1008`, `LMCEMR 0x1010`,
   `LMTYPE 0x1014`, `LMTIM 0x1018`, `LMREFRESH 0x101C`, `LMPROTMIN 0x1020`,
   `LMPROTMAX 0x1024`, `LMPROTCFG 0x1028`
3. **Graphics plane:** `GSCTRL 0x2000`, `GBBASE 0x2020`, `GDRCTRL 0x2040`, `GSCADR 0x2060`,
   `GSADR 0x20C0`, `GPLUT 0x2150`
4. **Video plane:** `VSCTRL 0x2004`, `VBBASE 0x2024`, `VCMSK 0x2044`, `VSCADR 0x2064`,
   `VUBASE 0x2084`, `VSADR 0x20C4`, `BGCOLOR 0x2174`
5. **Hardware cursor:** `HCCTRL 0x2100`, `HCSIZE 0x2110`, `HCPOS 0x2120`, `HCBADR 0x2130`,
   `HCCKMSK 0x2140`
6. **Display timing and control:** `DSCTRL 0x2154`, `DUCTRL 0x230C`, `DHT01..03 0x2158–0x2160`,
   `DVT01..03 0x2164–0x216C`, `DVECTRL 0x2310`, `DHDET 0x2314`, `DVDET 0x2318`,
   `DODMSK 0x231C`, `DBCOL 0x2170`, `DSIG 0x2184`, `DVLNUM 0x2308`, `DMCTRL 0x2188`,
   `DINTRE 0x217C`, `DINTRCNT 0x2180`, `DLLCTRL 0x2304`
7. **Scaler and clipping:** `CLIPCTRL 0x218C`, `SPOCTRL 0x2190`, `SVCTRL 0x2194`,
   `SHCTRL 0x21B0`, `SSSIZE 0x21D8`

`LCD_CONFIG` (0x060) is also accessed directly with a read-modify-write
(function at A08 VA `0x02110EA4`).

## Driver configuration (registry values read by the WM driver)

`CoreClock`, `SDRAMMemType`, `Panel`, `PanelExt`, `System\GDI\Gamma` → `Gamma Value`,
and `System\GDI\Rotation` (`DisableDynamicScreenRotation`, `RotationRemap`).
Default values to be extracted from the ROM registry hives (`default.hv`).

## Video overlay formats supported by the WM driver

UYVY, YUY2, YV12, IMC2 (plus 8888/A1 RGB variants), from the driver's format
table. Hardware WMV9 decode is in a separate driver (`wmv9decoder2700G.dll`).

## Measured on a real X51v (first light, 2026-10-11)

State as Windows Mobile left it, read by `rp-light` after HaRET's handoff
(photo of the device screen; the device runs a WM 6.1 Classic ROM, CE 5.2.20273).

| Register | Value | Meaning | Confidence | Evidence |
|---|---|---|---|---|
| `GSCTRL` | `0x3C0EFA7F` | RGB565 (`[30:27]` = 7), gamma enabled (`[26]`), 480 × 640 (`[21:11]` = 479, `[10:0]` = 639) | confirmed | rp-light on device |
| `GSCADR` | `0x80000000` | graphics plane enabled (`[31]`), start address 0 | confirmed | rp-light on device |
| `GSADR` | `0x0EC00000` | decodes to plane offset 0 in 2700G memory | confirmed | rp-light on device; `Plane::decode` kept it |
| Visible framebuffer | phys `0x0C000000` | start of CS3, i.e. 2700G memory offset 0 | confirmed | HaRET's physical FB address on the same device |

RetroPane draws into the plane WM configured without reprogramming the
display ("kept WM plane"), so the probe's report path works unchanged.
