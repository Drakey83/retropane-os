## What GC2DX adds to GC2DW

GC2DW (2026-11-08) guarded 960 KiB of free 2700G memory and every
texture. GC2DX also sums, after every render, the renderer's own memory:
its region array (480 / 8 x 640 / 16 tiles, 8 bytes each), the parameter
memory on the die (the lists), and the memory manager's 16 KiB block. The
CPU writes the same region array and lists for a frame every render, so a
frame's sums are fixed while it draws right.

## The first build (gpubench-0126): a baseline from the wrong place

It took each frame's sums from four renders at Windows Mobile's clock just
after the references. At 149.50 / 1 the region array and the lists
differed from those on frames 0, 1 and 3, every render (200 and 300 of
400 a part), so the stop rule fired. But the 149.50 / 2 control after it,
which drew every frame right, showed the very same sums (region array
0xbfa5cc72 and 0xb5f421b9, lists 0x54ada5ed), and the memory manager's
block never changed. The difference was in what the CPU writes before the
ladder and in it, not anything the core wrote. The run doesn't decide.
