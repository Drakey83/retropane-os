## The design (rule 0)

Windows Mobile's GWES repaints a window that comes back from its own
WM_PAINT, whole; Android keeps a recent app's last frame as a snapshot for
the switch animation only. Ours: Today's screen as left is kept in the
2700G's spare 600 KiB at `0x200000` (screen 0's old place, unused since
C71's ruling, so the pool gives nothing up), copied by one engine blit
queued ahead of the next frame (no CPU wait); while another screen is up
and still for a second (the 1 s compose rule), Today is composed ahead into
it whenever its list no longer matches the kept one (the app-ahead pattern
Reveal uses); the return copies it in and draws only where Today's list
differs from the kept list (`rp_draw::changes`, R191's diff). A kept
screen is used only if its copy landed whole and the wallpaper is the same
one (by generation, or by the caller's name for its own wallpaper), never
while the wallpaper reads bands from elsewhere; otherwise the return is
drawn whole, as before.
